## 一、建立"领域模板库"（Domain-Specific Templates）

v2.1 是"元框架（Meta-Framework）"，足够抽象。需要针对不同学科任务克隆定制"专属子模板"。

### 1. 数学建模竞赛模板（Math Modeling Edition）
- **定制点**：缩短阀门周期（12 小时一个节点），阶段 5 替换为"论文与代码数据强核对阶段"
- **外部模型群**：锁死一个精通 LaTeX 排版和公式推导的模型（ChatGPT-Plus / Claude Opus）

### 2. 嵌入式/硬件开发模板（Hardware Edition）
- **定制点**：模块 5 同步加固中增加"引脚图/寄存器映射表（Pinout Contract）"
- **外部模型群**：引入解析 Datasheet PDF 极强的模型（Gemini 1.5/2.0 Pro）
- **代码路由**：增加"寄存器安全范围 Assert 校验"

### 3. 科研论文/算法复现模板（Research Edition）
- **定制点**：阶段 1 锁定为"SOTA 算法数学原理公式锁死"
- **新增阶段**："Peer Review 模拟审查阶段"

## 二、自动化"物理网线"：轻量级脚本提效

混合模式下最大摩擦力是复制粘贴（MQTT 角色）。作为 CS/EE 方向学生，用代码消灭机械性劳动：

### mawf.py 本地命令行工具

```bash
# 自动检查点生成
python mawf.py checkpoint
# → git status 抓取已修改文件 → 读取编译日志末尾
# → 结合 项目状态_当前.md → 生成 Handoff Payload → 写入剪贴板

# 阶段回溯
python mawf.py rollback stage-X
# → git checkout stage-X-pass → 拉取历史归档 MD → 覆盖当前状态
```

**效果**：每天交互时间减少 80%，极大缓解长线项目疲劳感。

## 三、建立"工程摩擦力日志"（The Friction Log）

实战中的痛点是迭代的唯一燃料。高强度比赛中没时间修改规格书。

### 做法
- 项目根目录下放 `摩擦力.txt`（或记在手机便签里）
- 一旦觉得"阶段划分太累"、"CC#2 日志太长不想看"、"Assert 断言写起来太麻烦" → 立刻记下
- 比赛结束后第一天，花 15 分钟把 `摩擦力.txt` 喂给 Claude Code，对照 iteration.md 更新规格书

### 示例迭代
- 发现 Assert 很难维护 → 降级为"核心输入/输出格式断言"，放宽内部断言

## 四、动态维护"大模型路由表"

大模型能力在未来 6 年会发生多次洗牌（DeepSeek 崛起、OpenAI 新模型、Gemini 升级）。

### 做法
每当有业界公认强模型发布时，更新 spec.md 中的：
- 审查者模型分配表
- 外部模型群建议模型

### 恒定原则
- **本地执行端（CC#2）**：绑定当前本地 API 响应最快、Tool-use 能力最稳的模型
- **决策/审查端（CC#1）**：绑定长文本逻辑推理最强、幻觉率最低的模型

## 五、团队竞赛中的"1 分钟对齐协议"

不需要队友读 18 页规格书，只需制定极简协作协议：

### 三条规则
1. **代码全部由你的本地 CC#2 来跑**：队友只负责在本地写纯算法模块或 UI 模块
2. **契约优先**：分发任务时直接把 `项目状态_当前.md` 中"数据契约段（Variables/JSON Schema）"发微信群："所有人，输入输出格式按这个写死，谁改格式必须群里报备"
3. **无损数据流转**：队友交接代码时必须附带本地运行输入/输出日志
