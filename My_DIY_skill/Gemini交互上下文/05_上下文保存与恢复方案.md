# 上下文保存与恢复方案
> 来源：与 Gemini 3.1 Pro 的深度对话（四层保存方案 + 一键恢复提示词）
> 整理日期：2026-05-25

## 一、四层物理保存方案

不要依赖网页端"历史记录"（极易在清空缓存或平台更新时丢失）。将每次深度对话固化为本地物理文件。

### 第一层：固化工作流底层

在本机建立 `multi-ai-workflow/` 母版库：

```
multi-ai-workflow/
├── SKILL.md            # 核心 Skill 定义（v2.1，集成 Superpowers）
├── spec.md             # 完整技术规格（断点恢复、检查点、回溯协议）
├── usage-guide.md      # 使用指南
├── iteration.md        # 迭代改进机制
└── references/         # 未来存放项目模板
```

**用途**：未来任何新项目启动，直接把四个文件丢进新项目的 `references/` 目录。

### 第二层：保存项目启动种子

将项目 PRD 及定制的"项目启动总控文档"保存为 `Project_Kickoff.md`。开启项目时直接贴入本地 Claude Code 终端。

### 第三层：保存学术/技术路线图

保存 `Academic_Growth_Roadmap.md`，包含六年成长建议和阶段性策略。

**注意**：这个文件不需要给 AI 看，是写给自己看的心智模型。每当工程疲劳或不知道下个竞赛用什么姿态面对时，打开读一遍。

### 第四层：元上下文一键恢复提示词

保存为 `Recovery.txt`。大版本升级时（如 v2.2 → v3.0），直接复制给全新的 AI 实例，让其瞬间理解所有来龙去脉。

## 二、一键恢复提示词（完整版）

> 以下提示词以"高保真语义编码"撰写，能让新 AI 瞬间理解所有历史讨论。使用时直接全选复制。

```
# 恢复工作流元上下文指令

你现在需要协助我（一个本研一体化六年制的学生）对我们联合设计的「multi-ai-workflow 工作流」进行维护和迭代。为了让你瞬间恢复之前的完整心智模型，请读取以下历史推演摘要：

## 1. 历史演进背景

- [v1.0 阶段]：基于数学建模竞赛 C 题问题二的复盘（54M排列组合导致性能崩溃、after_idx=-1静默丢包、硬编码导致不同步），确立了"角色隔离"和"A/B/C审查分级"的原型。

- [v2.0 阶段]：推翻线性流水线，重构为【控制论星型中枢架构】。确立 CC#1 为中枢决策脑，CC#2 为本地执行代理。提出"用计算开销屏蔽执行噪声、保护中枢上下文"的底层理念。引入强制多模型交叉审查。

- [v2.1 阶段]：针对长周期项目，引入磁盘级 SSOT 检查点文件 `项目状态_当前.md`、Git Tag 阶段打标、原子化阶段回溯协议，实现"无状态 AI 会话的接力运行"。

## 2. 我们的底层共识

- 模型缺陷代偿：大模型天然无状态、长上下文注意力漂移、自我审查存在盲区。
- 我们的解法：用磁盘快照代替AI记忆，用本地副手屏蔽调试噪声，用多模型双盲交叉逼近全覆盖。
- 极简中继协议：用户扮演"只读数据网线（MQTT）"，在本地 API 与网页端 Web UI 之间无损传递 Handoff Payload，严禁人脑手动修改代码破坏契约。

## 3. 我们的 6 年战略愿景

- 大一/大二：通过高纪律性跑通大作业与大数模竞赛，训练高级系统架构思维。
- 大三/研究生：用于复现 SOTA 算法论文、撰写学术论文，并进行学术 Peer Review 模拟。

请确认你已完全吸纳并恢复了上述上下文，并等待我的下一步指令。
```

## 三、物理存档清单

| 序号 | 文件 | 用途 |
|------|------|------|
| 1 | `multi-ai-workflow/` 文件夹（4 个核心文件） | 母版库，新项目直接复用 |

## 四、使用场景

| 场景 | 操作 |
|------|------|
| 开启新项目 | 把母版库 4 文件丢进新项目 `references/` → 把 `Project_Kickoff.md` 贴入 CC#1 |
| 工作流大版本升级 | 复制 `Recovery.txt` 给新 AI → 讨论迭代方案 |
| 工程疲劳/迷茫 | 打开 `Academic_Growth_Roadmap.md` 阅读 |
| 更换电脑/重装系统 | 从备份恢复 `multi-ai-workflow/` 文件夹即可 |
