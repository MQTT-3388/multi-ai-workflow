  A. 一句话讲清楚
================================================================
  你开3个窗口（CC#1 + CC#2 + 外部AI），按规则协作，
  你只负责复制粘贴。核心流程：

  讨论需求 → CC#1指挥 → CC#2干活 → 外部AI挑刺 → CC#1拍板


  B. 你需要准备什么
================================================================
  ┌──────────────┬─────────────────────────────────┐
  │    窗口      │             用途                │
  ├──────────────┼─────────────────────────────────┤
  │ Claude Code  │ CC#1·中枢大脑                  │
  │ (1个窗口)    │ 指挥全局·拍板决策·不写代码      │
  ├──────────────┼─────────────────────────────────┤
  │ Claude Code  │ CC#2·副手                      │
  │ (再开1个)    │ 写代码·运行·出图·只汇报结论    │
  ├──────────────┼─────────────────────────────────┤
  │ 浏览器Tab    │ 外部审查者                      │
  │ (1~2个)      │ Gemini/GPT网页版·只挑刺不改代码 │
  └──────────────┴─────────────────────────────────┘

  最少：3个窗口。不能再少了。


  C. 四步搭建（10分钟）
================================================================

  ┌─ 第1步：启动工作流（1分钟）─────────────────┐
  │                                              │
  │  在你的主Claude Code输入：                    │
  │                                              │
  │  "启动多AI工作流。                            │
  │   项目类型：数学建模。                         │
  │   协作模式：hybrid。"                         │
  │                                              │
  │  CC#1会先和你讨论需求：                        │
  │  · 你要做什么？有什么约束？成功标准？          │
  │  · 一轮轮聊清楚 → CC#1输出设计文档            │
  │  · 你批准后 → CC#1拆解阶段                    │
  │                                              │
  │  ⚠️ 设计没批准之前，CC#1不会让你写代码。       │
  │     这是故意的——需求没聊清楚就写，后面全白做。 │
  └──────────────────────────────────────────────┘

  ┌─ 第2步：搭CC#2（1分钟）─────────────────────┐
  │                                              │
  │  新开一个Claude Code窗口，输入：               │
  │                                              │
  │  "你是CC#2副手。你的首要职责是保护CC#1的       │
  │   上下文。承接代码编写、运行、测试、图表。      │
  │   结果用精简格式汇报，不倾倒原始日志。          │
  │   确认后等我给你任务。"                        │
  │                                              │
  │  CC#2确认后，把CC#1给你的项目框架发过去。      │
  └──────────────────────────────────────────────┘

  ┌─ 第3步：搭外部审查Tab（30秒）───────────────┐
  │                                              │
  │  浏览器开新Tab（一定要新的！无痕模式最好）     │
  │  打开Gemini/ChatGPT，输入：                   │
  │                                              │
  │  "你现在是静态审计员。唯一职责是找Bug和        │
  │   逻辑漏洞。禁止输出可运行代码。请确认职责。"  │
  │                                              │
  │  ⚠️ 每次审查都用新Tab，不要复用旧的！         │
  └──────────────────────────────────────────────┘

  ┌─ 第4步：初始化Git（10秒）───────────────────┐
  │                                              │
  │  CC#1会让你在项目目录执行：git init           │
  │  这一步让工作流可以"时光倒流"到任意阶段出口。  │
  └──────────────────────────────────────────────┘


  D. 日常操作（你每天只需做3件事）
================================================================

  之后你所有的工作就是复制粘贴：

  ┌──────────────────────────────────────────────┐
  │  1. CC#1 → CC#2                              │
  │     复制CC#1的任务指令，粘贴给CC#2             │
  ├──────────────────────────────────────────────┤
  │  2. CC#2 → CC#1                              │
  │     复制CC#2的汇报，粘贴回CC#1                │
  ├──────────────────────────────────────────────┤
  │  3. CC#1 → 外部AI → CC#1                     │
  │     复制CC#1指定的内容，贴到浏览器新Tab        │
  │     拿到审查意见后，粘贴回CC#1                │
  └──────────────────────────────────────────────┘

  你不写代码 · 不改文字 · 不做决策 · 只做快递员。


  E. 关机 / 第二天 / 崩溃恢复（v2.1 新增）
================================================================

  这是v2.1最重要的新功能。之前关机后第二天不知道从哪开始，
  现在有检查点文件自动记录一切。

  ┌─ 每天关机前（CC#1会自动提醒你）─────────────┐
  │                                              │
  │  1. CC#1自动输出一段检查点文本                 │
  │  2. 你花10秒钟看两眼（确认阶段号和关键数据     │
  │     没被AI写错）                              │
  │  3. Ctrl+C 复制 → 保存为 项目状态_当前.md     │
  │  4. 关电脑                                    │
  │                                              │
  │  耗时：1分钟。                                │
  └──────────────────────────────────────────────┘

  ┌─ 第二天开机（30秒恢复）─────────────────────┐
  │                                              │
  │  新开CC#1 → 粘贴：                           │
  │  "恢复项目。读取 项目状态_当前.md。"          │
  │                                              │
  │  新开CC#2 → 粘贴：                           │
  │  "恢复项目。读取 [CC#2恢复用部分]。"          │
  │                                              │
  │  双方确认 → 继续干活。                        │
  └──────────────────────────────────────────────┘

  ┌─ CC#1开始绕圈子/废话变多（上下文满了）──────┐
  │                                              │
  │  告诉CC#1："你现在上下文满了，写检查点切换。" │
  │  CC#1会自动输出检查点 → 开新CC#1 → 恢复。    │
  │                                              │
  │  不慌。这是v2.1设计好的标准操作。             │
  └──────────────────────────────────────────────┘

  ┌─ 发现阶段方向错了，想回退───────────────┐
  │                                              │
  │  告诉CC#1："回溯到阶段X出口。"               │
  │  CC#1会读取历史检查点，CC#2回退代码。         │
  │                                              │
  │  只能回退到"阶段阀门通过"的节点。             │
  └──────────────────────────────────────────────┘


  F. 三条红线 + 必须做的事
================================================================

  ❌ 绝对不能碰的红线：
  ┌──────────────────────────────────────────────┐
  │ 1. 设计没批准就写代码                         │
  │ 2. 跳过外部交叉审查就定稿                     │
  │ 3. 没有验证证据就声明完成                     │
  │ 4. 手动修改AI写的代码（想改→让CC#2改）        │
  │ 5. 跳过CC#1直接让CC#2做事                     │
  │ 6. 传递信息时加自己的理解（你是快递员不是翻译）│
  │ 7. 复用旧浏览器Tab发审查（旧Tab会让AI偷懒）   │
  └──────────────────────────────────────────────┘

  ✅ 必须做的事：
  ┌──────────────────────────────────────────────┐
  │ CC#1说交叉审查 → 必须发外部AI                 │
  │ 阶段通过 → 才能做下阶段                       │
  │ 外部AI意见 → 原样贴回CC#1                    │
  │ 每次审查 → 开全新浏览器Tab                    │
  │ 每天关机前 → 保存检查点文件                   │
  │ 保存检查点前 → 花10秒人眼确认阶段号和数据     │
  └──────────────────────────────────────────────┘


  G. 常见问题
================================================================

  Q1: 只有Gemini一个外部模型，够用吗？
  ─────────────────────────────────────────────
  → 够用。审完一轮后关Tab，重开新Tab再审一轮。
    这叫"会话级降级"。两轮意见都贴回CC#1。


  Q2: 搞不清现在在哪个阶段了？
  ─────────────────────────────────────────────
  → 直接问CC#1："现在在哪？下一步做什么？"
    或者打开 项目状态_当前.md 看一眼。


  Q3: CC#2说了一大堆我看不懂的代码？
  ─────────────────────────────────────────────
  → 不用看懂。直接复制粘贴回CC#1。
    CC#1看的是"通过了没"，不是代码细节。


  Q4: 不敢做决策，怕做错？
  ─────────────────────────────────────────────
  → 你不需要做技术决策。CC#1综合所有外部意见后
    告诉你"采纳A、驳回B"，你跟着做就行。


  Q5: CC#2掉线了（窗口关了/VSCode崩了）？
  ─────────────────────────────────────────────
  → 重新开窗口，把CC#1给你的最新任务发过去。
    关键文件在磁盘上，代码在git里，不会丢。


  Q6: CC#1一直在看代码细节，感觉跑偏了？
  ─────────────────────────────────────────────
  → 提醒它："你是CC#1中枢，不要陷入代码细节。
    把任务分流给CC#2。"
    如果还不行 → 让它写检查点切新会话。


  Q7: 这个工作流和superpowers冲突吗？
  ─────────────────────────────────────────────
  → 完全不冲突。superpowers提供工具（brainstorming、
    代码审查、调试等），这个工作流告诉你这些工具
    在什么时候、按什么顺序、由谁调用。


  Q8: CC#1长时间运行后开始绕圈子/废话变多？
  ─────────────────────────────────────────────
  → 这是上下文老化的正常现象。告诉CC#1：
    "写检查点，准备切新会话。"
    CC#1会在当前决策完成后输出检查点文件，
    你开新窗口恢复即可。这是v2.1的标准操作。


  H. 工具自动调用清单（你不需要管什么时候调）
================================================================
  CC#1会在合适的时机自动触发以下工具：

  阶段0   brainstorming → 讨论需求·输出设计
  阶段规划 writing-plans → 生成正式计划
  CC#2执行 subagent-driven-development → 并行任务
  高难算法 web-access → 搜GitHub/论文参考
  A/B审查 requesting-code-review → 标准化审查
  发现Bug  systematic-debugging → 根因追溯
  阶段完成 verification-before-completion → 验证
  论文撰写 doc-coauthoring → 结构化协作

  你不需要记住这些。CC#1会自动判断和调用。
