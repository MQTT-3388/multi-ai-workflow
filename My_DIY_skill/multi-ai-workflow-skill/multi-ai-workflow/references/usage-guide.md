# 多AI协作工作流 v2.1 — 使用指南

## 谁需要

- 协调≥3个AI完成复杂项目的人
- 项目>4h，需保护中枢AI上下文
- 对正确性有硬性要求，需多模型交叉验证
- 本地Claude Code + 网页端混合使用者

## 不适合

单人单AI简单问答 | 实时调试 | EDA | 需求剧烈变动 | 单文件脚本

## 快速启动

1. "启动多AI工作流。项目类型：XX。协作模式：hybrid。"
2. CC#1自动定义角色→拆解阶段→输出框架
3. 开CC#2新会话 + 外部审查Tab
4. 按CC#1引导执行

## 最少配置

CC#1(1个会话) + CC#2(1个独立会话) + 1个外部模型(1个浏览器Tab) = 3个窗口

## FAQ

**Q: 为什么CC#2不能和CC#1同一个会话？**
A: CC#1的上下文是最稀缺资源。CC#2的代码编写/运行/调试会产生大量噪声（日志、报错、数据），在独立会话中执行保护CC#1的决策空间。

**Q: 只有一个外部模型怎么办？**
A: 启用会话级降级。新Tab+清空上下文+Temp=0+角色锁定，执行2轮独立审查。

**Q: 用户(我)可以手动改代码吗？**
A: 不可以。只读中继原则——你在AI间只做信息传递。需修改→告诉CC#2执行。

**Q: 交叉审查C级和A级有什么区别？**
A: A级审"算法对不对"（控制流/边界/契约），C级审"结果看起来合理吗"（数值范围/清单核对）。交叉审查(D级)审"有没有盲区"（独立视角发现你没想到的问题）。

**Q: 什么结果必须触发强制交叉审查？**
A: 数学模型定稿、核心算法结果、论文初稿/终稿、交付下游的数据。一句话：错了会导致连锁崩溃的。

**Q: 外部模型意见不一致怎么办？**
A: 一致指出→必改。分歧→CC#1追问双方深挖→研判→拍板。最终决策权在CC#1。

## 从C题学到的

1. 数据用JSON/CSV透传，不硬编码
2. 高优先级项必须在最终结果中出现
3. 审查加"为什么"比"改什么"有用
4. 伪代码阶段先审算法思路，省掉重写
5. CC#2保护CC#1上下文是最被低估的价值
6. 单AI盲区是系统性的——必须交叉审查

## 降级底线

最恶劣条件（纯网页+单模型+隔夜冷启动）：硬隔离Tab+交接快照+降级审查仍可运转。不可降级：执行与审查的物理隔离、阀门、终审。
