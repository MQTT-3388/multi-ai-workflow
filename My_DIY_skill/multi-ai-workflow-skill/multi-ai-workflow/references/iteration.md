# 工作流迭代改进机制

## 迭代原则

每次迭代的触发源必须是真实项目中的问题，不是凭空设想。

## 触发条件

- 完成一个新项目
- 同一模块连续2次失效
- 用户反馈某模块"用起来太累"
- 新AI工具/模型发布

## 迭代流程

1. 收据数据（阶段用时/bug类型/阀门触发/摩擦点）
2. 分析模式（未触发/反复不解决/被绕过/漏bug）
3. 修改规格（一次一个模块，保留旧版对照）
4. 下个项目验证

## 版本历史

### v2.0 → v2.1（2026-05-24）
**触发**：DeepSeek无持久记忆 + VSCode终端无记忆 + 以天/周为周期的项目需求

**核心变更**：
- 模块5升级为检查点系统：`项目状态_当前.md`统一快照·覆盖前备份到 `.workflow_history/`·关机/切换/回溯三重协议
- 模块8升级为四层防御体系：L1分流→L2告警(含CC#2独立告警)→L3切换(含CC#2自我切换)→L4磁盘快照
- 新增阶段回溯机制：git tag + 原子回溯指令。仅锚定阀门点
- 新增CC#2上下文自我管理：独立告警信号+不需等决策的切换规则
- 新增防维护疲劳机制：CC#1自动输出检查点文本·CC#2每次产出立即存盘

### v1.0 → v2.0（2026-05-24）
**触发**：C题项目实战反馈 + 3轮Gemini交叉审查 + CC#2执行者复盘

**核心变更**：
- 架构：线性流水线 → 星型中枢(CC#1控盘)
- CC#2定位：执行者 → 保护CC#1上下文的副手
- 外部模型：1个建模者 → 5类按需工具群
- 新增模块7：强制交叉审查(3层降级)
- 新增模块8：上下文保护机制
- 新增模块9：用户只读中继协议
- 模块10重构：双盲审查 → CC#1驱动多轮对话

**来源**：
- CC#2复盘：无声bug、数据硬编码、全排列→回溯教训
- Gemini Pro第1轮：JSON契约、伪代码预审、模型图谱
- Gemini Pro第2轮：判定阈值、防御断言、降级策略
- 深水区三问：混合模式协议、快照健壮性、审查介入点
- Gemini Flash终审：控制论框架、上下文屏障价值、人机总线
