目的：从本次C题项目中提取"哪些是通用的，哪些是这次特有的"。

操作：
1. 重读复盘报告，标记"如果换一道题还会遇到"的部分
2. 列出这次项目中的通用模板：
   - 数据提取阶段（PDF→Python dict）
   - 数学模型阶段（Gemini Pro生成LaTeX）
   - 算法设计阶段（枚举+TOPSIS）
   - 论文撰写阶段（Gemini生成初稿→CC#1审查→迭代）
   - 附录+支撑材料打包
3. 列出这次特有的部分（赛题特定，不放进skill）：
   - 10景点数据
   - 车程矩阵
   - 午餐三策略
   - A2落选分析

```
# 数学建模竞赛工作流

## 竞赛模式
- 外部代码：仅参考思路，独立重写（竞赛合规）
- 论文：必须符合对应竞赛格式规范

## 阶段模板
### 阶段1：题目理解+数据提取
- 输入：赛题PDF
- 输出：data.py（结构化数据）+ 题目分析文档
- AI: Gemini Flash提取 + CC#1验证

### 阶段2：数学模型建立
- 输入：题目要求+数据
- 输出：model.tex（带编号的LaTeX公式）
- AI: Gemini Pro生成 + CC#1审查

### 阶段3：算法设计与实现
- 输入：数学模型+数据
- 输出：stageN_optimization.py + 运行结果
- 高难度算法触发伪代码预审
- 竞赛模式：外部搜索→思路提取→独立重写

### 阶段4：可视化+时序表
- 输入：最优方案
- 输出：CSV + 甘特图PNG
- 数据通过JSON透传，不硬编码

### 阶段5：论文撰写+终审
- 输入：模型+结果+图表
- 输出：论文章节（Word/LaTeX）
- AI: Gemini Pro初稿 → CC#1审查 → 迭代
- 终审：硬约束核验+静默bug检测
```

## 第3步：编写Skill文件（2小时）

1. 打开 `~/.claude/skills/` 目录

```yaml

  - multi-ai-workflow  # 底层协作框架

  - web-access         # 外部代码搜索
  - docx               # 论文Word生成

  - brainstorming      # 赛题分析
```

## 第4步：用C题数据做回归测试（30分钟）

目的：验证skill能否复现本次项目的流程。

操作：
1. 开新对话，输入：
   ```
   启动数学建模项目。题目：C题"五一五日自驾游"。
   这是赛题PDF：[附文件]。模式：hybrid。
   ```
2. 让Claude按skill自动执行阶段1~5
3. 对比自动执行结果与本次真实项目结果：
   - 数据提取是否完整？
   - 阶段划分是否合理？
   - 审查标准是否正确触发？
4. 标记差异点，修正skill

---

## 第5步：迭代优化（赛后）

3. 补充 `formula-library.md`（新遇到的公式类型）
4. 更新 `competition-rules.md`（如果规则有变）

## 注意事项

1. **不要照搬C题数据**：skill里放的是模板和流程，不是具体数据。C题10景点数据放在case文件里作为参考，不写进SKILL.md
2. **竞赛合规优先**：模块8的外部搜索必须默认竞赛模式，非竞赛模式作为可选手动开启
3. **格式规范跟随最新**：`paper-format-guide.md` 需在每次比赛前确认规范是否有更新
4. **skill不宜过细**：只约束"每个阶段做什么"，不约束"每行代码怎么写"。留空间给实际题目灵活调整
